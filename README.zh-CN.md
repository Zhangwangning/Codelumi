# Codelumi

[English](README.md) · **简体中文**

一个把快递短信里的取件码收起来的 iOS App。数据只留在本机，不联网、不上传、不需要注册。

对外名称是 **Codelumi**（中文名「珞米」，只在关于页与商店中文页出现一次）。

Bundle ID、App Group、iCloud 容器、小组件扩展、仓库与工程目录已全部统一为 `codelumi` / `Codelumi`。更名链路：拾码（快捷指令）→ Allude（早期构建的工程代号）→ Codelumi（正式名）。

Codelumi 是一个独立、纯离线的工具。功能来自作者本人的开源快捷指令项目与日常取件流程，不取用任何其他 App 的功能或界面。

## 创意来源：先有一个快捷指令

这个 App 不是从「做个产品」开始的，是从一个快捷指令开始的。

快递短信一天来好几条，取件码散在短信里，取件时得翻聊天记录、对着屏幕手输。于是先写了「快递取件码」快捷指令：用正则把短信里的取件码抓出来，格式化好，复制到剪贴板或者存进备忘录。后来陆续加了多码拆分、驿站名、取件地址。

那个快捷指令的源码与规则在 [shortcut_pickup_code](https://gitee.com/zhang_wangning/shortcut_pickup_code)（Gitee 镜像，GitHub 版同步中）。

这套东西在小范围传开之后，收到的反馈很一致：

- 截图要自己存，存完还是找不到；
- 想要「已经取过的」和「还没取的」分开；
- 想要桌面上直接看到，不想每次点开；
- 想要到驿站的时候提醒一下；
- 一条短信两个码的时候，快捷指令分不干净。

这些反馈说明一件事：**基于短信的取件码收集是真实需求**，不是凭空想出来的功能。但快捷指令有天花板：没有列表与搜索，没有分组与排序，没有提醒与小组件，每跑一次多一条「自动化已运行」通知，正则改起来也只能在一个动作里硬编码。

所以把那套解析规则整体搬进原生 App，做成了 Codelumi。仓库里仍然留着那个快捷指令的项目与语料，App 的解析规则至今和它同源——四条正则、优先级链、字段口径都从那里长出来，然后在真机语料上一条条补齐。

## 它做什么

- 把短信或截图里的取件码抠出来，连同快递公司、驿站、地址、柜位货架一起存成一条记录
- 待取 / 已取分两个列表，可以按时间、按快递公司、按取件地点分组排序
- 桌面小组件和实时活动直接显示最新的几条，不用打开 App
- 到达取件地点时的提醒（可选，需要定位权限，也可以完全不启用）
- 统计、搜索、批量标记已取、分享取件码

## 工作逻辑

**1. 短信怎么进来**

三条路，用户自己选：

- iOS 27 起可以在设置里一键导入「收到短信 → 添加到 Codelumi」的自动化（更早的系统按教程手动建一条）
- 截图收件：相册或截图里选一张，识别文字
- 手动粘贴：把整条短信复制进来

**2. 怎么解析**

解析以规则为主。四套独立正则 + 一条优先级链（取件码 → 运单号 → 尾号 → 特殊格式），每条短信取第一个命中的形态。一条短信里有多个取件码时按「同形」拆成多张卡——链式段必须和首段形态一致，否则柜位号会被误判成第二个码。

产出字段：取件码、快递公司、驿站 / 代收点、取件地址、柜位货架。

驿站名只按词表里的 `name` 与 `aliases` 匹配，**不用短名**（比如「中邮」这种）——短名扫正文会把「中邮大厦」判成驿站。自定义驿站可以自己加名字，加完直接参与匹配。

**3. 驿站怎么归**

驿站可以归到一个「组」，组是一个取件地点，有自己的名字、图标和位置。一个驿站只属于一个组；个别记录不在这组取的，可以在详情页单独指定。待取 / 已取 / 小组件的组间排序是同一套：件数多的在前，同数按名字，「未标注驿站」置底。

**4. 存在哪**

本机 `Application Support` 里的 JSON。记录有上限，超了按先进先出淘汰最旧的——这只在收到新短信入库时触发，启动不会删东西。

可以选择开启 iCloud 同步：写进**你自己的** iCloud 云盘（`Documents/Codelumi/records.json`），不经过开发者服务器。合并粒度是单条记录，同一个 id 取更新时间新的那份；删除会留墓碑，免得另一台设备把删掉的记录同步回来。

**5. 端侧智能只做补位**

规则没抓到的字段，交给 Apple 的端侧模型补一刀，把结果补完整。除了这个补位动作，解析完全由规则决定：**只填空，不覆盖**——尤其不改已经抓到的取件码。端侧模型不可用（国内机型常见）时，就是少这层补位，其余功能不受影响。

## 安全基线

这是这个项目最在意的一条：**App 没有要把数据发出去的理由，也没有发出去的通道。**

- 没有开发者服务器、没有域名、没有第三方 SDK、没有 API Key
- 代码里没有发起网络请求的地方。可以自查：

```bash
grep -rn "URLSession\|URLRequest\|NSURLConnection" Codelumi/Codelumi Codelumi/CodelumiShared Codelumi/CodelumiWidget
# 无输出
```

- App 里唯二涉及网络的，都是 Apple 自己负责的部分：iCloud 同步（默认关闭，写你自己的云盘）与 App Store 相关能力
- 诊断日志只记「发生了什么」：版本、系统、解析长度与条数、错误码、耗时。不写短信原文、取件码、地址、电话、设备标识
- 没有账号体系，因此也没有「找回密码」「同步到我们的云」这类东西

## 怎么编

```bash
cd Codelumi
xcodebuild -project Codelumi.xcodeproj -scheme Codelumi \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/codelumi-verify build \
  CODE_SIGNING_ALLOWED=NO OTHER_SWIFT_FLAGS="-disable-sandbox"
```

`-disable-sandbox` 是给宏插件（`swift-plugin-server`）留子进程用的，不是修代码。构建进程被沙箱包住时会抛一批假错误（典型是 `SwipeActionRow.swift` 里的 `'self' is immutable`），那是工具链问题，别去改业务代码。
