# 2026-11-21 · 修「同意并继续点了没反应」+ 通知弹窗盖引导页

## 症状
老大实测：首启同意页勾选后点「同意并继续」，页面纹丝不动，点了十几次。
诊断日志里有 14 条 `[consent] accepted` —— 按钮**点了有效**，是页面退不出去。

## 根因（两层）
1. `RootView` 上挂了**两个** `fullScreenCover`（分别盯 `showConsent` / `showOnboarding`），
   `acceptConsent()` 在同一次状态更新里「关一个、开另一个」→ 两个呈现槽互抢，卡死。
2. 改成 `onDismiss` 接力后仍不通：主界面 `PickupListView.onAppear` 会弹系统通知授权，
   那个弹窗把引导页的呈现**顶掉**。

## 修法
- 收成**一条呈现通道 + 阶段状态** `RootTabModel.launchStage: LaunchStage?`（`.consent` / `.onboarding` / nil），
  单一 `fullScreenCover` 由 `LaunchGateView` 按 stage 换内容 —— 不关不重开，无抢占位。
- `RootTabModel.isLaunchGateActive`（static）：首启门开着时 `PickupListView.onAppear`
  **不问**通知权限；门关后由 RootView `.onChange(of: launchStage)` 延迟 0.45s 统一问一次。
- `init` 顺序：**先初始化没有默认值的 `selection`**，再读 `launchStage`，否则
  `'self' used before all stored properties are initialized`。

## 🔴 排查陷阱（重要）
iPhone 16 Pro 模拟器上**怎么都复现不了**（干净安装后 `consented=true onboarded=true`）——
`simctl uninstall` 没清干净，cfprefsd 把偏好缓存带回来了。
**换未跑过该 App 的模拟器，或 `simctl erase`** 才能拿到真正的首启状态。
另外 `SCREEN=consent` 是脚手架直渲，**不经过门控** —— 拿它验首启流程是假验证。

## 新增脚手架
`AUTO_ACCEPT_CONSENT=1`（自动点同意）、`AUTO_FINISH_ONBOARDING=1`（自动点开始使用），
把「同意页 → 引导页 → 待取页 → 通知授权」整条链路一次跑完。

## 验证（iPhone 17 抹机后从零跑）
1. 首启 → 同意页，**无通知弹窗**，勾选框未勾选 ✓
2. 自动同意 → 引导页「欢迎使用 Codelumi」，**无通知弹窗** ✓
3. 引导完成 → 待取页 + 通知授权弹窗（此时才出现）✓
4. 未勾选点同意 → 自动勾上 + 确认框（同意 / 查看条款 / 不同意红色）✓
构建 0 error / 0 warning。
