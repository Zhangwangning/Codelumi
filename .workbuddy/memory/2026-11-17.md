## 卡顿排查（320 反馈：Tab 切换卡 + 一键取件卡）

### 方法
- `xctrace record --template 'Time Profiler' --attach <pid>` 采样主线程（18s）。
- 导出 `time-profile` 表 → Python 按 **id→name 引用表** 解析，算 inclusive。
- 新增 `FrameMonitor`（`PERF_FPS=1`）：CADisplayLink 数帧间隔，按 16.7/33/50/100ms 分桶。
- 新增 `PerfProbe`（`PERF_LOG=1`）：分段测各步耗时，2 秒冲刷到 `Documents/perf.log`。

### 实测结论（模拟器 iPhone 16 Pro / iOS 26.1，9 条待取、50 条记录）
- **切标签**：16.1s / 889 帧，掉帧率 19%，最长 126.6ms。
  慢帧归因：启动首帧 83ms；**首次进已取 127ms / 统计 103ms / 设置 105ms**；切回待取 60/52ms。
- 主线程 1505 采样里 1363 在 SwiftUI runloop：
  `ViewGraphRootValueUpdater.render` 399 + `CA::Transaction::commit` 305 ≈ 69%。
- **我们的业务计算不是瓶颈**：`displayed` 54 次共 **4.3ms**，`stationMatch` 47 采样（0.x ms）。
  → 卡在 SwiftUI 首次构建每页视图树 + 每次切换的视图图重算 / 图层提交。
- **一键取件**：`completeAll` 全链 **54.9ms** 同步阻塞（写盘 21.3 / 提醒 6.2 / 读盘 2.5 / 小组件 1.4）。
  改一次性建索引后 **21.4ms**（写盘 6.6 / 提醒 2.8 / 小组件 2.0 / 读盘 1.0）。

### 已改
- `markAllPendingAsPicked`：O(n²) `firstIndex(where:)` → 一次建 `[UUID: Int]`。
- 三处脚手架全在 `#if DEBUG`，Release 包不含。
- ⚠️ 模拟器 CoreAnimation 走软件合成，render+commit 占比被放大；真机需另测。

### 踩坑
- 采样前必须确认**有待取数据**（`AUTO_ONECLICK` 会把 50 条全标已取，之后 perf 计数全为空）。
- `simctl install` 后 data container UUID 会变，`get_app_container` 要重新取。
- `xctrace --template 'Animation Hitches'` 在模拟器上直接失败，只能用 CADisplayLink 自测。
- `xcodebuild -configuration Debug SWIFT_OPTIMIZATION_LEVEL=-O` 可保留 DEBUG 宏同时开优化，
  用来区分「Debug 慢」与「真慢」。

## 推广短信误判（训练样本反馈）

用户导出 `codelumi-training.jsonl` 里一条华为云推广短信被标 `label=other`，
却带着 `code=glm-5`、`platform=华为云` —— 说明它**真的入库**过，用户手工改的判定。

三层误判叠加（实测复现）：
1. `keywordPattern` 里 `京东` 命中「京东卡」（营销奖品）；
2. `codePattern` 通用分支 `(\d?\+?[A-Za-z]+?(-?\d+)+)` 字母≥1位、数字≥1位太宽，
   前置逗号满足 lookbehind，从 `glm-5.3-flash` 截出 `glm-5`；
3. 品牌词表从「千万 token 天天送」认出「天天」当快递公司。

修法（三处独立、互不依赖，任一处都能单独挡住）：
- ②.6 新闸门 `isPromotionalOnly`：营销话术 + **零**取件线索，两条同时成立才拒。
  🔴 不能只凭「拒收请回复R」——真实驿站短信也常带这句，单条件会杀一片。
- `keywordPattern` 的 `京东` → `京东(?!卡)`。
- `isVersionLikeCode`：`^[A-Za-z]{2,}-\d{1,2}$` 视为版本号。收得很窄，
  `YT8861234`/`A-12`/`8-4-3019` 不受影响。
- 训练样本 `save()`：判「不是」时清空 code/address/platform/locker，
  否则训练集里出现 `label=other 却有 code` 的矛盾样本。

验证：回归 64/64 识别、63/64 地址无回退；6 条边界用例（含 2 条带「拒收请回复R」
的真实驿站短信）全部符合。

⚠️ 遗留：手机上那条历史样本/记录仍是脏的，需用户手动删或重存一次。

## 流畅度优化（第二轮，实测驱动）

### 手段与结果（模拟器 iPhone 16 Pro / iOS 26.1，9 待取 + 40 已取，16s/轮 × 3 取中位）
| 指标 | 基线 | 优化后 |
|---|---|---|
| 100ms 以上冻结次数 | 3~4 | **0~1** |
| 最长单帧 | 126.6ms | **99ms** |
| 掉帧率 | 19.0% | 17.9% |
| 设置页首次进 | 247ms | **57~74ms** |
| 统计页首次进 | 103ms | **56~83ms** |
| 已取页首次进 | 127ms | 91~105ms |
| 一键取件 | 54.9ms | **20.8ms** |

### 改了什么
1. `displayed`（待取页过滤+排序）按 key 记忆化：14s 内 68 次访问 → **只算 1 次**；
   `stationName` 336 → 22 次。缓存放 `PickupListModel`（body 期间写 @State 违法）。
2. Store 新增 `revision`（records didSet +1）做失效判据 —— 数组比较是 O(n) 且要逐字段比。
3. 🔴 **缓存键必须用 hashValue 不能用 count**：驿站改名 / 组换成员时数量不变，
   用 count 会一直命中旧分组，退出重进也不恢复（缓存活在 model 里）。
4. 设置页 `VStack` → `LazyVStack`（几十行设置项首帧全建，247ms 的主因）。
5. 统计页 `VStack` → `LazyVStack` + `StatsCache`（PickupStats 一次渲染重算 4~6 遍）。
   代价：`proxy.scrollTo` 到未构建的卡失效 —— 那入口只有截图脚手架用。
6. `PadLayout.windowSize` 加 100ms 缓存：`row(for:)` 每行都判 `usesSplit`，
   50 行 = 50 次 `connectedScenes→windows` 遍历。
7. 景深 blur 5 → 3：它与 `scaleEffect` 一起被隐式动画驱动，弹簧每帧都要
   对整屏做高斯模糊（离屏渲染整棵子树）。

### 经验
- 模拟器测量**波动极大**（同一改动 picked 出现 143/230/257ms），单轮不可信，必须 3 轮取中位。
- 对比必须**固定数据条件**（待取/已取条数），否则掉帧率数字没有可比性。
- 剩余成本几乎全在 SwiftUI 首次构建页面 / UIKit 首次创建渲染资源，
  业务计算已降到可忽略（displayed 单次 0.8~3.4ms）。
