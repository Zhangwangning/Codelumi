# 2026-11-22 · 小组件款式库收尾（探索页 / 玻璃底卡 / 8 款小尺寸）

## 探索页（`WidgetSettingsView`）
- 边距四轮收敛：24pt → 12pt → **4pt**（主人最终口径「卡片内边距 4pt」）。
  `sideInset = topInset = 4`、`bottomInset = 10`（下面放名字）、`nameGap = 8`。
- 列间距：24pt → **8pt**（`columnSpacing = 8`）；行间距 24pt → **12pt**（`rowSpacing = 12`）。
- 列数可变：**小尺寸一行 4 个**，其余一行 2 个。`sections` 元组带 `columns`，
  `cardWidth(columns:)` 按列数算（4 列 = 96pt/张）。
- 窄卡（`box < 120`）走紧凑口径：名字 11.5pt、nameGap 6、bottomInset 8。
- 底色卡片 = **玻璃**：`.appGlass(cardShape)` —— 走 `GlassSettings`（外观页「液态玻璃」
  开关，App Group `codelumi.usesLiquidGlass`）→ iOS 26+ 开 = 真 `glassEffect`，
  关/低版本 = `.ultraThinMaterial` 毛玻璃 + 淡描边。
- 底色卡片圆角 **四角统一 = 24**，与里面小组件**同源**：新常量 `WidgetCanvasMetrics.cornerRadius`
  （定义在 `WidgetPreviewGallery.swift`，`WidgetCanvas` 与卡片都引用它，禁止再各写数字）。

## 01:1x 🔴 背景开关口径纠错（我原来理解错了）
- 主人原话：「使用 Liquid Glass 打开的话是小组件有了液态玻璃的材质效果，不是变成了透明；
  两个都打开才是全透明的液态玻璃的材质」。
- 所以**两个开关正交可叠加**，不是三选一互斥：
  · `clear` 只透明（不画底，透壁纸）
  · `glass` 只玻璃（**默认底还在**，玻璃只是表面材质）
  · `clear + glass` = 全透明液态玻璃（不铺底 + glassEffect 浮空）
- 数据层改成两个 App Group 键 `codelumi.widget.clear` / `codelumi.widget.glass`；
  `WidgetBackground` 变四组合渲染枚举（solid/clear/glass/clearGlass），由 `resolve(clear:glass:)` 算。
  旧键保留只读，`migrateLegacyIfNeeded()` 一次性迁移（老用户升级不掉设置）。
- 详情页两个 Toggle 各自独立写键、各自 `reloadAllTimelines()`，**不做联动**。
- 已验证：`WIDGET_BG=clearGlass` → 两开；`WIDGET_BG=glass` → 只玻璃开。

## 01:2x 尺寸筛选菜单对齐（对照 Apple 提醒事项）
- 症状：菜单项「全部尺寸/小/中/大/超大」文字不齐 —— 选中项被对号推右，其余靠左。
- 根因：`Button { } label: { if item == filter { Label(_, systemImage: "checkmark") } else { Text(_) } }`
  —— 只有选中项有图标位，文字起点逐行不同。
- 改法：Menu 里放 `Picker("", selection: $filter) { ForEach { Text(_).tag(_) } }.pickerStyle(.inline)`，
  系统给每一项预留同一图标位，对号不占新位置 → 文字天然左对齐（Apple 菜单标准写法）。
- ⚠️ macOS 侧 computer-use 未授权（辅助功能/屏幕录制），无法自动点开菜单截图，未做视觉验证。

### 16. 小组件透明/玻璃开关"没反应"（23:00 老大截图）
- 老大：「这两个开关要起到真实的作用啊，不是打开了而没有反应，第一个开关的标题改成
  可用时使用真正透明，iOS27 已经支持了的」，随后澄清：「真正透明的意思是添加到桌面后
  小组件的背景就是真正的透明的」。
- **根因一（真 bug）**：App 内预览的画布 `WidgetCanvas` 把背景写死成
  `Color(.secondarySystemBackground)`，**完全不读 `codelumi.widget.clear / glass`** ——
  在设置页拨开关，下面缩略图一动不动，用户当然认为开关是假的。
  修法：`WidgetCanvas` 用 `@AppStorage(store: AppGroup) ` 直接绑两个键，背景分四态
  （solid / clear / glass / clearGlass），与 `WidgetSurface` 一一对应；开关本身也换成
  `@AppStorage` + `onChange { reloadAllTimelines() }`。
- **根因二（平台边界，不是 bug）**：iOS 26+ 起小组件背景**由系统按桌面外观接管**。
  Apple 论坛 iOS 27 实测（thread 845586）：`containerBackground { Color.clear }` 在
  **Clear / Tinted 桌面外观**下由系统给透明/玻璃；在**默认外观**下 widget 仍是 `.fullColor`，
  系统容器**不透明，壁纸透不出来**，第三方无法绕过。所以这个开关只能控制
  "App 要不要额外画一层实底"，最终观感由系统外观决定 —— 标题写「可用时」正是这个意思。
  设置页因此在开关下加了一行说明：「背景最终由 iOS 桌面外观决定：外观选『透明』或『着色』时才看得到玻璃与透明。」
- 验证方法（模拟器）：App Group 的 plist 在 **App 沙盒** `Library/Preferences/group.com.jikezhang.codelumi.plist`，
  `xcrun simctl spawn <udid> defaults write group.com.jikezhang.codelumi` 写的是另一个文件、App 读不到；
  改文件后 cfprefsd 还会缓存。**正路是用脚手架 `WIDGET_BG=solid|clear|glass|clearGlass`**
  （走 `WidgetBackgroundSetting` 正式 setter）。
- ⚠️ 改完代码记得 `simctl install` 再截图，否则拍的是旧包（这次踩了，白折腾一轮）。
